# Terminology

This file is the project's glossary: one place where every term the code and the docs
use is defined once. It is **glossary only**. Design rationale lives in `docs/`, indexed
by [`docs/CLAUDE.md`](./docs/CLAUDE.md); each entry below links to the file that owns
its subject.

Every entry describes the shipped system. Where an entry states a constraint, that
constraint is enforced in code, and the entry names the error it produces.

| Term | Meaning |
|---|---|
| **Venue** | A `uint16` identity (`venue_id`) that owns its own sequence-number space. One file holds exactly one venue's records; one merge cursor covers exactly one venue, and two cursors may not share one (`merge.ErrDuplicateVenue`). Sequence gaps are normal. A sequence number is **not** unique within a venue: one venue can emit the same one for two instruments at the same timestamp, which is why `instrument_id` is in the ordering key. See [`docs/format.md`](./docs/format.md). |
| **Venue partition** | The set of files holding one venue's data, presented to the merge as a single ordered sequence by one `merge.Cursor`. The files must be given in ascending time order, and every one must carry the same venue (`merge.ErrVenueMismatch`). An empty file set is a valid empty partition: it yields nothing but still occupies a loser-tree leaf. See [`docs/merge.md`](./docs/merge.md). |
| **Ordering key** | `(exchange_ts int64, venue_id uint16, sequence_number uint64, instrument_id uint32)`, compared in that order. It defines the total order of the replay stream, and `merge.compareKey` is the only thing that defines it. `instrument_id` is the final tie-break, because the first three fields alone are not unique. An equal key is `merge.ErrDuplicateKey` and a backwards key is `merge.ErrOutOfOrder` — never a tie broken by arrival order, goroutine identity, or a clock. See [`docs/format.md`](./docs/format.md). |
| **Sentinel key** | The all-maximum ordering key an empty or exhausted cursor holds. It sorts after every real key, so such a cursor loses every match and keeps its leaf instead of being removed from the tree. See [`docs/merge.md`](./docs/merge.md). |
| **Loser tree** | The fixed-size tournament tree the k-way merge uses, never `container/heap`. It costs `log2(k)` comparisons per pop, about half a binary min-heap's. The property the determinism guarantee rests on is not the speed: the tree's shape is settled by `k` at construction and never changes, however the data is distributed and however many cursors run out. Leaves past `k` are padded with the sentinel key to a power of two. See [`docs/merge.md`](./docs/merge.md). |
| **Cursor (merge)** | `merge.Cursor`: an iterator over one venue partition. It hides file boundaries, verifies each block's checksum once on first touch, enforces the ordering key across file seams, attaches snapshot blobs, and owns and closes the partition's files. One goroutine owns it. See [`docs/merge.md`](./docs/merge.md). |
| **Cursor (subscriber)** | The next emit index one subscriber wants, published atomically so the writer's Block barrier can read it. Nothing to do with files. See [`docs/backpressure.md`](./docs/backpressure.md). |
| **Emit index** | A global, contiguous, monotonic `uint64` assigned by `fanout.Ring.Write` from the ring's own `writeSeq` counter: one per emitted record, starting at zero. It is the unit of gap reporting and of a subscriber's cursor and start position — never a venue sequence number. See [`docs/backpressure.md`](./docs/backpressure.md). |
| **Emit loop** | The single goroutine that drains a `merge.Merger` into a `fanout.Ring`, through `Ring.Run` or `Ring.RunPaced`. It is a ring's only writer, and it is where join and leave requests are applied between records. |
| **Shared ring** | The fixed-capacity buffer holding recently emitted records, written by the emit loop and read by every subscriber through its own atomic cursor — one buffer, not a channel and a goroutine per subscriber. Capacity is a power of two of at least two, so a slot index is a mask rather than a modulo (`fanout.ErrCapacity`). A slot's record is stored as atomic words, never a plain struct, because a Drop reader may copy a slot the writer is concurrently overwriting. See [`docs/backpressure.md`](./docs/backpressure.md). |
| **Block** | The backpressure mode that promises no loss. Before overwriting the slot for emit index `n`, the writer waits until the minimum cursor over every registered Block subscriber has passed that slot's current occupant — so it may run up to a full ring ahead of the slowest, and waits only when the slowest falls a whole capacity behind. An empty Block set never holds the writer back. See [`docs/backpressure.md`](./docs/backpressure.md). |
| **Drop** | The backpressure mode with bounded, always-reported loss. The writer never waits for a Drop subscriber and never inspects one; on overflow the oldest unread data is what goes. The subscriber detects this itself on its next read and receives the exact gap attached to the record that follows it. See [`docs/backpressure.md`](./docs/backpressure.md). |
| **Lapping** | The writer overwriting a ring slot a subscriber has not yet read. A reader detects it through the slot's own generation counter and turns it into an exact gap. Only a Drop subscriber is ever lapped at runtime: the Block barrier makes it impossible for a registered Block subscriber. A Block subscriber whose start position was already overwritten *before it joined* is rejected at subscribe time with `fanout.ErrStartLapped`. See [`docs/backpressure.md`](./docs/backpressure.md). |
| **Gap** | `fanout.Gap`: `(FirstMissedIndex, LastMissedIndex, Count)`, always in global emit indexes, with `Count` always `LastMissedIndex - FirstMissedIndex + 1`. It is delivered attached to the record that follows it, never as a separate frame, and it is never part of the canonical hash — a gap is delivery framing, not content. See [`docs/backpressure.md`](./docs/backpressure.md). |
| **Eviction, cancellation** | The two out-of-band subscriber stops: `fanout.ErrEvicted` from the stalled-Block-subscriber watchdog, and `fanout.ErrCanceled` from `Cancel` or `Unsubscribe`. They are the only errors the fan-out package itself produces, because they are the only places a run's outcome is not settled by content and order alone. See [`docs/backpressure.md`](./docs/backpressure.md). |
| **Canonical projection** | `canonical_v1`: the explicit, versioned field projection the determinism test hashes — the eight scalar record fields, plus `level_count` and the decoded blob payload for a snapshot pointer. Never raw struct or file bytes. `blob_offset`, `blob_len`, the reserved bytes and any capture-time field are excluded, because they say where a snapshot sits in one file rather than what it holds. Each record is length-prefixed; the run ends with the record count and the terminator `CANONv1\x00`. CRC-32C by default, SHA-256 on request. See [`docs/format.md`](./docs/format.md). |
| **SimClock** | The `Clock` implementation the tests and the determinism suite run on. It has no autonomous time: `SleepUntil` returns immediately and never moves the clock, and simulated now advances only when a caller calls `Advance`, which then fires every due timer in ascending `(deadline, registration order)`. See [`docs/clock.md`](./docs/clock.md). |
| **Snapshot epoch** | A contiguous run of snapshot-pointer records emitted by `cmd/convert`, one per instrument it has seen in that venue, all carrying the same `exchange_ts` and consecutive sequence numbers in ascending instrument order. The cadence is a record count per venue, but the epoch lands at the next strict `exchange_ts` increase, so its keys strictly increase by construction. It bounds seek cost to one epoch's worth of deltas. An epoch missing an instrument is possible, and a consumer falls back to an earlier one. See [`docs/convert.md`](./docs/convert.md) and [`docs/book.md`](./docs/book.md). |
| **Pacing** | Converting a record's `exchange_ts` into a delivery deadline — `t0 + (ts - base) * den/num`, against the injected `Clock`, with a 128-bit intermediate product and no float — and waiting for it. The anchor pair is set once at the first record and never moved. Records due inside one measured release-batching window are released together, and a record is never released more than one window early. Pacing never reorders, drops, duplicates or coalesces a record; it only delays the one the emit loop already chose. See [`docs/clock.md`](./docs/clock.md). |
| **Speed** | An exact rational replay multiplier, `num/den` as two `int64`, reduced to lowest terms at construction so that two spellings of one speed are one value. Never a `float64`: Go fuses floating-point multiply-add on some target architectures and not others, and pacing timing decides when a Drop subscriber gets lapped, so a float would make gap output architecture-dependent. The wire carries the two integers for the same reason. See [`docs/clock.md`](./docs/clock.md). |
